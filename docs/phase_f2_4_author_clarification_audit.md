# TerraSpectra Phase F2.4 - Author Clarification and Dataset Expansion Assessment

**Audit date:** 2026-11-27
**Project:** TerraSpectra: Hyperspectral Crop Disease Forecasting
**Scope:** Public-source documentation review and readiness assessment for the three already acquired *Alternaria protenta* cubes. No new raw data were downloaded; no arrays or existing reports were changed; no models were trained; no production preprocessing or Botrytis integration was performed.

## Executive decision

| Question | Decision | Basis |
|---|---|---|
| Alternaria descriptive spectral exploration | **CONDITIONAL GO** | Three distinct, checksum-verified inoculated-plant cubes are technically inspectable. Keep analysis source-separated and descriptive. Wavelength-aware spectral analysis and physical interpretation must wait for clarification of the full wavelength vector, axis order, units, and calibration. |
| Alternaria supervised ML evaluation | **NO-GO** | The public cube subset has no control cube, only three plants in one trial, no severity labels or per-cube diagnostic confirmation, and unresolved wavelength/calibration semantics. A valid plant-level evaluation cannot be formed. |
| Zenodo Botrytis/Healthy integration | **NO-GO** | Preserve the existing F3 decision: duplicate healthy arrays, no verified plant mapping or wavelength vector, calibration uncertainty, and large class-scale differences remain unresolved. |
| Cross-dataset disease classification | **NO-GO** | Similar host/camera family or overlapping bands do not establish measurement comparability. Alternaria, Botrytis, and bacterial leaf spot have distinct pathogens, experiments, sensors/protocols, and label provenance. A justified, separately designed study would be required. |

This is a readiness assessment, not a model-performance result. No predictive performance is claimed.

## Baseline and repository safeguards

The existing Phase F2.2 and F2.3 reports were read and left unchanged. Their evidence establishes three distinct, non-duplicate NPZ cube arrays (`1797`, `1827`, `1855`), each mapped by the source TSV to an inoculated plant: two isolate `028`, one isolate `065`. There is no public control cube among these three. The arrays have shape `512 x 512 x 204`, dtype `float16`, and contain no embedded wavelength, calibration/reference, or sample-metadata arrays. The existing Phase F2.3 report keeps the Zenodo Botrytis/Healthy integration at **NO-GO**.

The branch is `main`, tracking `origin/main`. At inspection, there were no tracked or staged changes; unrelated untracked user files were present and preserved. No existing phase report, raw cube, or production source was modified.

## What is needed before Alternaria ML evaluation

### Minimum gates for exploratory analysis

Before wavelength-aware spectral plots or comparisons:

1. Verify the exact wavelength vector and band ordering for each cube, and identify bad/dropped bands and the spectral-axis order.
2. Obtain units and the radiometric meaning of array values; document the calibration procedure and the associated dark/white references. Until resolved, keep values in explicitly labeled stored-array units and do not call them reflectance.
3. Use a reviewed sample-level join for cube ID, trial, independent plant, isolate/control, leaf/part, capture date, and experimental conditions. Keep repeated parts/captures grouped by plant.
4. Confirm file integrity and ensure no unintended preprocessing or wavelength-vector reuse from another dataset.

With these gates, the three existing cubes may support bounded, source-separated description of the three observed plants. They cannot establish class differences, disease progression, or biological generalizability.

### Additional gates for defensible supervised evaluation

In addition to exploratory gates:

- Obtain independent plants for every intended class, including healthy controls and the intended pathogen/isolate groups. Include enough independent plants to allocate train, validation, and test partitions at the plant level without empty classes or reusing the same plant across partitions.
- Include multiple prospectively defined disease severity/progression stages if the scientific question concerns progression or forecasting. Record assessment method, timing, and sample linkage.
- Verify pathogen/isolate identity and control status using a defensible inoculation and/or diagnostic protocol, with sample-level ground-truth records.
- Supply plant-level metadata, repeated-observation identifiers, inoculation/capture dates, greenhouse/acquisition conditions, cultivar, trial, sensor settings, reference captures, wavelength calibration, and consistent measurement units/calibration across samples.
- Predefine a plant-grouped train/validation/test strategy. All leaves, parts, captures, and pixels from an individual plant must stay in one partition. Pixel count, leaf count, or file count cannot substitute for biological replication.
- Plan sample size from expected between-plant variability, class balance, intended model complexity, target effect/precision, and the intended test design. There is no universal minimum plant count appropriate to every claim.

No sample size is asserted here. For an exploratory descriptive study, the current three verified plants can be described after measurement semantics are clarified; they are not enough for supervised evaluation.
